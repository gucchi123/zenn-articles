個人の自動化プロジェクトで、30近い媒体に毎日コンテンツを流している。9月に入って、外部リンクのクリックが7〜8月の約5分の1に落ちた。

最初に疑ったのは「表示回数（IMP）が減った」ことだった。実際、ある媒体の週次の表示合計は 9,115 → 1,428 と 8割以上落ちていた。ところが、これは**合計で見たから**そう見えただけで、1本あたりの数字はまったく変わっていなかった。

この記事は、その読み違いの中身と、同じ失敗をしないための集計の型のメモ。

## 症状: 週次の合計が8割落ちている

媒体ごとに、各投稿の表示回数を毎日スナップショットで取っている。形はこう。

```text
fetched_at_jst,post_id,posted_at,views,replies,...
2026-09-22 21:20:05,1810...,2026-08-29T08:30:51,7019,11
```

これを「投稿した週ごとに views を合計」すると、問題の媒体はこうなった。

| 投稿週 | 本数 | views 合計 |
|---|---:|---:|
| 8/17 | 22 | **9,079** |
| 8/24 | 20 | **8,444** |
| 8/31 | 20 | 2,080 |
| 9/14 | 20 | 1,655 |

本数は毎週ほぼ同じなのに、合計が 9,000 → 1,600。「届かなくなった」と読むのが自然に見える。

## 原因: 合計を2本が支配していた

同じ表に、中央値と「上位3本が合計に占める割合」を足す。

```python
import statistics
from collections import defaultdict

by_week = defaultdict(list)          # 投稿週 -> [views, ...]
for row in latest_rows:              # post_id ごとの最新スナップショット
    by_week[week_of(row["posted_at"])].append(int(row["views"]))

for wk, vs in sorted(by_week.items()):
    vs.sort(reverse=True)
    total = sum(vs)
    print(wk, len(vs), total,
          statistics.median(vs),
          f"{sum(vs[:3]) / total:.0%}")   # 上位3本の占有率
```

| 投稿週 | 本数 | 合計 | 中央値 | 上位3本の占有率 |
|---|---:|---:|---:|---:|
| 8/17 | 22 | 9,079 | 58 | **84%** |
| 8/24 | 20 | 8,444 | 37.5 | **88%** |
| 8/31 | 20 | 2,080 | 38.5 | 50% |
| 9/14 | 20 | 1,655 | 59 | 44% |

中央値は 37〜59 のまま動いていない。8月後半の山は、**同じ質問投稿が2回ヒットした（6,011 と 7,019）だけ**だった。合計は「平常の20本」ではなく「ヒットの2本」を測っていた。

![同じ週次データを、合計と中央値・上位3本の占有率で読んだときの違い](/images/median-not-sum-two-readings.png)

つまり結論はこう変わる。

- 合計で見る: 届かなくなった（落ちた）
- 中央値で見る: 平常運転。ヒットが出ていないだけ

打つ手もまったく違う。前者なら配信の仕組みを疑うが、後者なら「何がヒットしたか」を調べるべきだ。

## ヒットの中身を見ると、次の一手が出る

ヒットした2本を分類してみると、共通点がはっきりしていた。

```python
def kind(text: str, is_referral: bool) -> str:
    q = re.search(r"(ますか|ですか|どう|みなさん)[？?]|[？?]\s*$", text)
    return "question" if q else ("referral" if is_referral else "other")
```

| 型 | 本数 | views 中央値 | 返信がついた率 |
|---|---:|---:|---:|
| 質問で終わる投稿 | 30 | **206** | **37%** |
| リンク付きの告知 | 92 | 32 | 0% |
| その他 | 51 | 38 | 4% |

質問で終わる投稿だけが会話（返信）を生み、それが表示を押し上げていた。さらに投稿時刻で割ると、**朝の質問投稿**が突出していた。

そして、ここに2つ目の落とし穴があった。

## もう1つの原因: タスクを登録し直したら実行時刻がずれていた

朝に出していたはずの日次投稿が、ある日から夕方 17:12 に出るようになっていた。Windows のタスクスケジューラの設定を読むと、原因はすぐ分かった。

```powershell
(Get-ScheduledTask -TaskName DailyPost).Triggers | Select-Object StartBoundary
# StartBoundary : 2026-09-05T17:12:00+08:00
```

別件でタスクを登録し直したとき、トリガーの開始時刻に**登録した瞬間の時刻**が入っていた。以後、朝の枠ではなく夕方に出続け、質問投稿への返信はぴたりと止まった。エラーは一度も出ていない。

```powershell
$t = New-ScheduledTaskTrigger -Daily -At '08:30' -RandomDelay (New-TimeSpan -Minutes 45)
Set-ScheduledTask -TaskName DailyPost -Trigger $t
```

直したあとは、必ず `StartBoundary` を読み戻して確認するようにした。

## 対処と教訓

1. **週次の比較は、合計・中央値・上位3本の占有率を並べる。** 占有率が高い週は、合計を「平常の変化」として読まない
2. **ヒットは分類して理由を探す。** 合計の上下を追うより、何が当たったかを見るほうが次の一手になる
3. **スケジューラを触ったら、実行時刻を読み戻す。** 再登録で時刻が静かにずれることがある

外部リンクのクリックが落ちた本当の原因は、表示ではなかった（それは別途、人の承認を待つ工程で投稿が止まっていたことだった）。ただ、最初に「表示が落ちた」と読んでいたら、そこに気づくのはずっと後になっていたと思う。数字が大きく動いたときほど、まず集計の仕方を疑うようにしている。
