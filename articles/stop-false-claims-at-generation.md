個人プロジェクトで、携帯回線の情報を扱う解説動画とポッドキャストを毎日自動で作って公開している。台本もタイトルも生成AIが書き、人が見るのは公開後だ。

2026-09-28 の朝、その公開物に「パートナー回線が9/30終了?」というタイトルが並んでいるのに気づいた。キャリアの公式のお知らせ（9/5）はそうは言っていない。10月から「十分カバーできているエリア」ではパートナー回線を縮小し、カバーに時間がかかるエリアでは継続する、という内容だった。

同じ話題に人手で書いていた返信は、どれも正しく「一部エリアで縮小」と書いていた。**間違っていたのは生成の仕組みのほうだった。**

## 何が起きていたか

原因は2つ重なっていた。

1. **生成プロンプトの例示に、誤った前提が入っていた。** 台本を作る前に検索させるクエリの例として、テンプレートに `2026-09-30 au ローミング終了` と書いてあった。モデルは例をそのまま手本にする
2. **タイトルの自動書き換えが、中立な見出しを煽った。** クリックされやすい形に直す工程が「パートナー回線 10月からの変化」のようなタイトルを「9/30終了?」に書き換えていた

「?」が付いていても、見出しだけ読む人には「終わる」と伝わる。

見つけたのは関門ではない。公開済みの中身を毎日読み返しているレポートの中で目に留まった。さかのぼると、YouTube のタイトルと概要欄で16本、加えてポッドキャストの RSS に同じ型の文言があった。これらは公式の言い方に合わせて全部書き直した。

ただ、出力を直すだけでは翌日また同じものが生成される。そこで生成側と関門の両方に手を入れた。

## 関門の判定

判定は正規表現1本と、同じ文の中を見る窓でできている。

```python
# 主語: パートナー回線 / au回線 / ローミング（海外・国際ローミングは除く）
_SUBJ = (r"(?:パートナー回線|au\s*(?:回線|網|ローミング)|KDDI\s*(?:回線|ローミング)|"
         r"(?<!海外)(?<!国際)(?<!海外で)ローミング)")
# 述語: 終わる系 +「9/30まで」
_END = (r"(?:終了|終わ|停止|廃止|打ち?切|なくな|無くな|使えなくな|卒業|"
        r"(?:9\s*/\s*30|9月30日|9月末)\s*まで)")
CLAIM_RE = re.compile(_SUBJ + r"[^。\n｜|]{0,20}?" + _END)

# 限定・否定の語が同じ文の近く（前15字〜後25字）にあれば言い切りではない
QUALIFIER_RE = re.compile(r"(縮小|一部|継続|わけでは|ではない|誤解|...)")
```

主語のあと20字以内に「終了」系の語が来たら候補にする。その文の中に「縮小」「一部」「継続」「わけではない」があれば通す。窓は句点と改行で切っている。概要欄の別の箇条書きに「エリア縮小」と書いてあっても、見出しの言い切りは免罪しない。

## 置いた場所は4か所

![言い切りの関門を置いた4か所](/images/stop-false-claims-at-generation.png)

| | 場所 | 見るもの |
|---|---|---|
| ① | アップロード直前（タイトル書き換えの後） | タイトル・概要欄 |
| ② | 動画のビルド前 | 台本のタイトル・ナレーション・字幕 |
| ③ | 翌朝の品質チェック | その日に公開されたもの全部 |
| ④ | ポッドキャストに含める前 | エピソードのタイトル |

①は書き換えの**後**に置くのが要点だ。書き換え前のタイトルが通り、書き換え後だけが引っかかる場合は、止めずに書き換え前へ戻して公開を続ける。

```python
if (orig_title and orig_title != title and partner_line_end_reason(title)
        and not partner_line_end_reason(orig_title)):
    meta["title"] = orig_title   # 書き換えだけが原因なら元に戻す
```

②は動画生成の課金より前で止めるために置いた。③は二重目の網にあたる。①は緊急時のフラグで外せるので、すり抜けたものを翌朝に拾う。

生成プロンプトの例示クエリも中立なものに差し替えた。回線の事実をまとめたファイルには、公式の言い方と「使ってはいけない言い方」「使ってよい言い方」を並べて書いた。

## 弾きすぎないためのテスト

テストは2つの束で固めている。

- **止めるべき文 10件**: 実際に公開されてしまったタイトルと概要欄の行
- **通すべき文 11件**: 「10月からパートナー回線が一部エリアで縮小」のような正しい言い方と無関係な話題（海外ローミング、「キャンペーンは9月30日まで」など）

加えて、キューに積んである約140本の台本に当てて誤検知が0件なのを確かめた。

通すべき側の束を作ったのには理由がある。以前、別の関門で日本語として正しい文を弾いてしまったことがあった。関門が弾きすぎても、出力が少し減るだけで異常には見えない。正しい言い方を固定しておかないと、そのまま気づかずに運用が続く。

## 学んだこと

- **直すのは出力ではなく生成の入り口。** 例示やテンプレートにある前提をモデルはそのまま事実として使う
- **関門は自動の書き換えより後ろに置く。** 前に置くと書き換えで生まれた言い切りを素通しする
- **止める例と同じだけ、通す例を持つ。** 弾きすぎは静かに起きる

公式の案内が変わったときは、関門を外さず、事実ファイルと関門の公式文言を更新する決まりにした。関門が見ているのは「言い方」ではなく「公式と合っているか」なので、基準の側を動かす。
